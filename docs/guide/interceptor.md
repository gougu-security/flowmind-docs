# 拦截器

拦截器允许您实时拦截、修改和控制在途的 HTTP 请求与响应。

![拦截器](/screenshots/拦截器.png)

## 功能概述

拦截器提供以下能力：

- **Hold**：暂停请求或响应，等待手动放行
- **Modify**：在放行前修改内容
- **Drop**：丢弃请求，不发送到目标服务器或客户端

## 启用拦截器

1. 进入 **拦截器** 页面
2. 点击 **启用拦截** 开关
3. 配置拦截规则（可选）

拦截器启用后，所有匹配规则的请求会被暂停在拦截队列中，等待处理。

## 拦截规则

### 按方法拦截

选择要拦截的 HTTP 方法：

- GET、POST、PUT、DELETE、PATCH、HEAD、OPTIONS

### 按域名拦截

配置要拦截的域名列表：

```
api.example.com
*.internal.company.com
```

### 按路径拦截

使用正则表达式匹配路径：

```
^/api/v1/users
^/admin/
```

## 拦截队列

当请求或响应被拦截时，会进入拦截队列：

| 字段 | 说明 |
|------|------|
| 方法 | HTTP 方法 |
| URL | 请求 URL |
| 方向 | 请求 / 响应 |
| 状态 | 等待中 / 已修改 / 已放行 / 已丢弃 |
| 拦截时间 | 请求被拦截的时间 |

## 操作请求

### 查看详情

点击队列中的请求，查看完整详情：

- 请求头
- 请求体
- 原始报文

### 修改请求

1. 选中要修改的请求
2. 点击 **编辑** 按钮
3. 修改请求内容：
   - 修改 URL
   - 修改请求头
   - 修改请求体
4. 点击 **保存修改**

### 放行请求

- **放行**：将请求（可能已修改）发送到目标服务器
- **批量放行**：选中多个请求，一次性放行

### 丢弃请求

- **丢弃**：丢弃请求，客户端将收到连接超时或错误
- **批量丢弃**：选中多个请求，一次性丢弃

## 响应拦截

除请求拦截外，拦截器也支持拦截来自服务器的响应：

1. 请求到达目标服务器后，响应返回时被拦截
2. 可在放行前修改响应头或响应体
3. 适用于调试响应内容、测试客户端行为

## 使用场景

### 参数篡改测试

```
1. 启用拦截器
2. 触发目标 API 请求
3. 在拦截队列中修改请求参数
4. 放行修改后的请求
5. 观察服务器响应变化
```

### 响应修改调试

```
1. 启用拦截器（包含响应拦截）
2. 触发请求
3. 在响应拦截中修改返回数据
4. 放行修改后的响应
5. 观察客户端行为
```

### 请求阻断

```
1. 配置域名或路径拦截规则
2. 匹配的请求自动进入队列
3. 丢弃不需要的请求
4. 客户端收到连接错误
```

## 注意事项

::: warning 性能影响
启用拦截器会显著降低网络性能，仅在需要时启用。
:::

::: tip 自动超时
被拦截的请求会在 60 秒后自动超时，请及时处理队列中的请求。
:::
